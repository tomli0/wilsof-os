# Wilsof OS — prosjektinstruksjon for Hermes

Følg aktuell oppdragsavgrensning, CONTRIBUTING.md og docs/ENGINEERING_STANDARDS.md. Dokumentasjon eller en anbefalt neste oppgave gir ikke operativ tillatelse. Bevar andres grener/worktrees/WIP og prosjektets prosess-/låseierskap.

## Fast avslutning — også ved blokkering eller kontrollert stopp

Rapportering er del av hver Wilsof-økts normale avslutning. Følg docs/development-reporting.md og docs/templates/DEVELOPMENT_REPORT_TEMPLATE.md:

1. Oppdater kontrollpunktet med faktisk tilstand og én neste trygg handling.
2. Skriv fullstendig sanert Markdown-rapport under docs/development-reports/, med alle 12 punkter og tydelig skille mellom historisk og nykontrollert bevis.
3. Commit og push bare egne godkjente endringer til autorisert gren. Les eksakt remote-head og publisert rapport tilbake.
4. Oppdater relevant status-issue (Wilsof-dashboard #16) med kort sammendrag og direkte rapportlenke; les oppdateringen tilbake. Ikke lukk feil uten faktisk verifikasjon.
5. Gi direkte GitHub-lenke i terminalen, kort status, tidsstemplet eksakt ledig diskplass og neste anbefalte oppgave. Stopp; ikke start neste oppgave.

Ingen rå samtalelogger, hemmeligheter eller private serveropplysninger til GitHub. Ingen ny QA/test/VM/ISO/installasjon for rapporteringens skyld. Ikke opprett eller start scheduler, bakgrunnsarbeider, plugin eller hook for rapporteringen. Ved publiseringsblokkering: bevar alt lokalt og rapporter eksakt hva som ikke er publisert; ikke påstå suksess.
